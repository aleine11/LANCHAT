# LanChat 项目架构与通信接口设计文档

> 版本：V1.0 | 日期：2026-07-30 | 状态：设计中

---

## 一、项目基本信息

| 项目名称 | LanChat（局域网聊天） |
|----------|---------------------|
| 项目定位 | 局域网内设备自动发现 + 实时聊天（文字+图片）工具 |
| 运行平台 | Windows 桌面端（后续可扩展 Mac/Linux） |
| 网络环境 | 同一局域网（WiFi / 热点），无需互联网 |
| 交互模式 | 类似 LocalSend 的设备发现 + 微信风格的聊天窗口 |

## 二、技术架构总览

### 2.1 技术栈

| 层级 | 技术 | 用途 |
|------|------|------|
| 桌面框架 | **Electron 28+** | 将Web应用打包为Windows桌面程序 |
| 前端框架 | **Vue 3.4+** + Composition API | 构建用户界面 |
| UI组件库 | **Element Plus** | 弹窗、按钮、输入框等基础组件 |
| 构建工具 | **Vite 5+** | 前端开发与打包 |
| 样式方案 | **SCSS** + CSS自定义属性 | 主题色变量管理，便于后期换肤 |
| 设备发现 | **Node.js `dgram`** (UDP组播) | 局域网广播设备上线/下线信息 |
| 点对点通信 | **Node.js `net`** (TCP) | 建立一对一聊天长连接 |
| 本地存储 | **SQLite** (better-sqlite3) | 聊天记录、配置信息的本地持久化 |
| 图片处理 | **Node.js `sharp`** | 图片缩略图生成、格式转换 |

### 2.2 Electron 双进程架构

```
┌─────────────────────────────────────────────────────┐
│                   Electron App                       │
│                                                      │
│  ┌─────────────────────────┐  ┌──────────────────┐  │
│  │    主进程 (Main Process)  │  │ 渲染进程 (Renderer)│  │
│  │                         │  │                  │  │
│  │  ● UDP 广播/监听        │  │  ● Vue 3 界面    │  │
│  │  ● TCP 服务端/客户端    │  │  ● 设备列表页     │  │
│  │  ● SQLite 数据库读写    │  │  ● 聊天窗口页     │  │
│  │  ● 文件系统操作         │  │  ● 设置弹窗       │  │
│  │  ● 系统托盘管理         │  │  ● 图片预览弹窗   │  │
│  │                         │  │                  │  │
│  │   ←── IPC 通信 ──→      │  │                  │  │
│  │  (ipcMain/ipcRenderer)  │  │                  │  │
│  └─────────────────────────┘  └──────────────────┘  │
│                                                      │
└─────────────────────────────────────────────────────┘
```

**大白话解释：**
- **主进程**是"管家"，负责网络通信（发现设备、收发消息）、数据库读写、文件操作这些底层工作
- **渲染进程**是"界面"，Vue 写的网页界面，只负责展示数据和处理用户点击
- 两个进程通过 **IPC**（进程间通信）对话，类似前后端API调用的概念

### 2.3 网络通信架构

```
同一个局域网 (192.168.1.x)

电脑A (192.168.1.5)               电脑B (192.168.1.3)
┌──────────────────┐              ┌──────────────────┐
│ UDP组播端口 5678  │◄──组播消息──►│ UDP组播端口 5678  │
│  ● 广播"我在线"   │              │  ● 广播"我在线"   │
│  ● 监听别人上线   │              │  ● 监听别人上线   │
│                  │              │                  │
│ TCP服务端 5679    │──TCP连接───▶│ TCP客户端 → 5679  │
│  ● 接收消息       │◄──发消息────│  ● 发送消息       │
│  ● 发送消息       │              │  ● 接收消息       │
└──────────────────┘              └──────────────────┘
```

**通信流程：**
1. 每台电脑启动时，在 **UDP 端口 5678** 上向局域网广播"我是XXX，IP是XXX，端口5679"
2. 其他电脑收到广播后，记录该设备信息，显示在列表中
3. 用户点击设备发起聊天时，向对方 **TCP 端口 5679** 建立连接
4. 连接建立后，所有文字/图片都走这个 TCP 通道

## 四、IPC 通信接口设计（相当于"后端API"）

> 由于 LanChat 没有传统后端服务，前后端通信通过 Electron IPC 完成。
> 以下"接口"指的是渲染进程（Vue界面）调用主进程（Node.js底层）的 IPC 通道。

### 4.1 IPC 通道命名规范

- 渲染进程 → 主进程（调用）：前缀 `invoke:` 表示请求-响应模式
- 主进程 → 渲染进程（推送）：前缀 `on:` 表示事件推送模式

---

### 4.2 用户配置模块

#### 设置用户名称
| 项目 | 内容 |
|------|------|
| IPC通道 | `invoke:set-user-name` |
| 调用方向 | 渲染进程 → 主进程 |
| 用途 | 修改自己的显示名称 |
| 请求参数 | `{ name: string }` — 新名称（1-20字符） |
| 返回数据 | `{ success: boolean, message: string }` |
| 异常情况 | 名称为空时返回 `success: false` |

#### 获取用户名称
| 项目 | 内容 |
|------|------|
| IPC通道 | `invoke:get-user-name` |
| 调用方向 | 渲染进程 → 主进程 |
| 用途 | 获取当前设置的显示名称 |
| 请求参数 | 无 |
| 返回数据 | `{ name: string, ip: string }` — 用户名 + 本机IP |
| 异常情况 | 未设置时返回默认名 `"用户-" + IP后两位` |

---

### 4.3 设备发现模块

#### 启动设备发现
| 项目 | 内容 |
|------|------|
| IPC通道 | `invoke:start-discovery` |
| 调用方向 | 渲染进程 → 主进程 |
| 用途 | 启动UDP广播监听，开始发现局域网设备 |
| 请求参数 | 无 |
| 返回数据 | `{ success: boolean, port: number }` — 返回UDP监听端口 |
| 说明 | 软件启动时自动调用 |

#### 停止设备发现
| 项目 | 内容 |
|------|------|
| IPC通道 | `invoke:stop-discovery` |
| 调用方向 | 渲染进程 → 主进程 |
| 用途 | 停止UDP广播，软件退出时调用 |
| 请求参数 | 无 |
| 返回数据 | `{ success: boolean }` |

#### 设备发现事件（主进程推送）
| 项目 | 内容 |
|------|------|
| IPC通道 | `on:device-discovered` |
| 推送方向 | 主进程 → 渲染进程 |
| 用途 | 发现新设备或设备信息更新时推送 |
| 推送数据 | `{ ip: string, name: string, hostname: string, firstSeen: string }` |

#### 设备离线事件（主进程推送）
| 项目 | 内容 |
|------|------|
| IPC通道 | `on:device-offline` |
| 推送方向 | 主进程 → 渲染进程 |
| 用途 | 设备超时无心跳，判定离线时推送 |
| 推送数据 | `{ ip: string, name: string }` |

---

### 4.4 聊天连接模块

#### 连接到设备（发起聊天）
| 项目 | 内容 |
|------|------|
| IPC通道 | `invoke:connect-device` |
| 调用方向 | 渲染进程 → 主进程 |
| 用途 | 点击设备卡片，发起TCP连接建立聊天通道 |
| 请求参数 | `{ targetIp: string, targetPort: number }` |
| 返回数据 | `{ success: boolean, message: string }` |
| 异常情况 | 连接失败（对方不在线等）返回 `success: false` |

#### 断开设备连接
| 项目 | 内容 |
|------|------|
| IPC通道 | `invoke:disconnect-device` |
| 调用方向 | 渲染进程 → 主进程 |
| 用途 | 关闭聊天窗口时断开TCP连接 |
| 请求参数 | `{ deviceIp: string }` |
| 返回数据 | `{ success: boolean }` |

#### 连接状态变化事件（主进程推送）
| 项目 | 内容 |
|------|------|
| IPC通道 | `on:connection-changed` |
| 推送方向 | 主进程 → 渲染进程 |
| 用途 | 聊天连接建立或断开时通知前端 |
| 推送数据 | `{ deviceIp: string, status: 'connected' | 'disconnected' | 'connecting' | 'error', message?: string }` |

#### 发送文字消息
| 项目 | 内容 |
|------|------|
| IPC通道 | `invoke:send-message` |
| 调用方向 | 渲染进程 → 主进程 |
| 用途 | 发送文字消息给已连接的设备 |
| 请求参数 | `{ targetIp: string, content: string }` |
| 返回数据 | `{ success: boolean, messageId: number, timestamp: string }` |

| 项目 | 内容 |

| IPC通道 | `invoke:send-image` |

| 返回数据 | `{ success: boolean, messageId: number, thumbnailPath: string, timestamp: string }` |

|------|------|

| 推送方向 | 主进程 → 渲染进程 |
| 用途 | 从TCP连接收到新消息时推送给前端 |
| 推送数据 | `{ fromIp: string, fromName: string, messageType: 'text' | 'image', content: string, thumbnailPath?: string, imagePath?: string, timestamp: string }` |

### 4.8 全局状态码一览

| 状态码 | 含义 |
|--------|------|
| 200 | 操作成功 |
| 400 | 参数错误 |
| 401 | 连接未建立 |
| 404 | 目标设备不存在 |
| 408 | 连接超时 |
| 500 | 服务器内部错误（主进程异常） |
| 1001 | UDP端口被占用 |
| 1002 | TCP端口被占用 |
| 1003 | 连接被对方拒绝 |
| 1004 | 图片格式不支持 |
| 1005 | 图片文件过大（最大20MB） |

## 五、全局设计规则

1. **无中心服务器**：完全去中心化，每台电脑同时是服务端和客户端
2. **UDP端口 5678**：固定用于设备发现广播
3. **TCP端口 5679**：固定用于聊天连接
4. **设备名称**：用户自定义，默认取计算机名
5. **心跳间隔**：每5秒广播一次心跳，15秒无心跳判定离线
6. **图片限制**：单张图片最大20MB，支持格式 jpg/png/gif/webp/bmp
7. **图片存储**：接收的图片存到用户目录 `{appData}/LanChat/images/` 下
8. **数据库路径**：`{appData}/LanChat/lanchat.db`
9. **聊天记录**：本地永久保存，用户可手动清除
10. **主题系统**：CSS变量管理，主题色定义在 `variables.scss` 中，后期可动态切换
