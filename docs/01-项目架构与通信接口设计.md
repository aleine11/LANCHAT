## 一、整体架构

```
┌──────────────────────────────────────────────┐
│                  同一局域网                    │
│                                              │
│  ┌──────────────────┐   ┌──────────────────┐ │
│  │  LanChat (电脑A)  │   │  LanChat (电脑B)  │ │
│  │                  │   │                  │ │
│  │  Electron 主进程  │◄──►  Electron 主进程  │ │
│  │  UDP 广播发现 ◄───┼───► UDP 广播发现     │ │
│  │  TCP 直连聊天 ◄───┼───► TCP 直连聊天     │ │
│  │  SQLite 本地存储  │   │  SQLite 本地存储  │ │
│  │                  │   │                  │ │
│  └──────────────────┘   └──────────────────┘ │
│        端口：5678 (UDP) / 5679 (TCP)          │
└──────────────────────────────────────────────┘
```

### 双进程模型

```
┌─────────────┐     IPC(preload)     ┌─────────────┐
│  渲染进程     │ ◄──────────────────► │   主进程     │
│  (Vue 3)     │                      │  (Node.js)   │
│              │   invoke:xxx  (15个)  │              │
│  显示界面    │ ◄──────────────────  │  UDP/TCP 通信 │
│  用户交互    │   on:xxx 事件(5个)    │  SQLite 数据库│
│              │  ──────────────────► │  图片存储    │
└─────────────┘                      └─────────────┘
```

## 二、UDP 设备发现（端口 5678）

### 广播包格式

```json
{
  "type": "lanchat-discovery",
  "hostname": "我的电脑",
  "port": 5679,
  "timestamp": 1670000000000
}
```

### 工作流程

1. 启动时：向 `255.255.255.255:5678` 广播自身信息
2. 持续监听 5678 端口，收到其他 LanChat 广播 → 加入设备列表
3. 每 15 秒重新广播（保持在线状态）
4. 超过 30 秒未收到某设备广播 → 标记为离线
5. **防重复**：已有相同 IP 的设备不再重复添加

### 关键实现

- `socket.setBroadcast(true)` 开启广播
- `255.255.255.255:5678` 全网段广播
- 自动识别本机 IP（非 127.0.0.1 的第一个地址）
- 异常处理：`EADDRINUSE` 端口冲突时自动重试

## 三、TCP 通信（端口 5679）

### 连接策略

**统一入口**：同一套 TCP Server 同时承接「被动接收」和「主动连接」。

```
┌────────── TCP Server (监听 5679) ──────────┐
│                                             │
│  ① 被动接收：对方主动连我                    │
│     → 'on:connection-changed' (connected)   │
│                                             │
│  ② 主动连接：我方连对方                      │
│     → connectToDevice(ip)                   │
│     → 'on:connection-changed' (connecting)  │
│     → 成功 → 'on:connection-changed' (connected)│
│     → 失败 → 'on:connection-changed' (disconnected)│
│                                             │
│  ③ 心跳检测：每 5 秒检查连接状态             │
│     → 断开 → 'on:connection-changed' (disconnected)│
└─────────────────────────────────────────────┘
```

### 消息格式

```json
{
  "type": "text" | "image",
  "messageType": "text" | "image",
  "content": "消息内容（文字 或 图片 base64）",
  "messageId": "uuid",
  "timestamp": "2026-07-31T12:00:00.000Z",
  "fromName": "用户名",
  "fileName": "图片文件名（可选）",
  "imageSize": 12345
}
```

### 消息处理流程

```
发送方                               接收方
┌──────┐                            ┌──────┐
│ 1. 写入 SQLite（is_self=1）       │       │
│ 2. TCP 发送                       │       │
│ 3. 成功→ status='sent'            │       │
│    失败→ status='failed'          │       │
│ 4. 更新联系人                     │       │
│ 5. 推送到 Vue 前端展示             │       │
└──────┘                            └──────┘
                           ────────►
                                    ┌──────┐
                                    │ 1. 收到图片→先保存到本地    │
                                    │ 2. 写入 SQLite（is_self=0）│
                                    │ 3. 更新联系人               │
                                    │ 4. 推送到 Vue 前端展示       │
                                    │ 5. 播放提示音（全局）        │
                                    └──────┘
```

### 断联重试机制

1. 对方上线时自动重连（触发于 UDP 发现）
2. 调用 `retryPendingMessages(deviceIp)` 扫描 `status='pending'` 或 `status='failed'` 的消息
3. 逐一 TCP 重发 → 更新状态为 `sent` 或 `failed`
4. 完成后推送 `on:retry-completed` 事件通知前端刷新

## 四、IPC 桥接层（preload.js）

### 15 个 invoke 通道（渲染进程 → 主进程）

| # | 通道名 | 功能 |
|---|--------|------|
| 1 | `invoke:set-user-name` | 设置本机用户名 |
| 2 | `invoke:get-user-name` | 读取本机用户名 |
| 3 | `invoke:start-discovery` | 启动 UDP 设备发现 |
| 4 | `invoke:stop-discovery` | 停止 UDP 设备发现 |
| 5 | `invoke:connect-device` | 主动 TCP 连接某设备 |
| 6 | `invoke:disconnect-device` | 断开 TCP 连接 |
| 7 | `invoke:send-message` | 发送文字消息 |
| 8 | `invoke:send-image` | 发送图片 |
| 9 | `invoke:retry-pending` | 重试待发送消息 |
| 10 | `invoke:delete-message` | 删除消息 |
| 11 | `invoke:get-chat-history` | 分页查聊天记录（旧版，保留兼容） |
| 12 | `invoke:get-all-messages` | ⭐ 全量查聊天记录（新版，直接加载全部） |
| 13 | `invoke:get-recent-contacts` | 获取最近联系人列表 |
| 14 | `invoke:get-unread-count` | 获取未读消息数 |
| 15 | `invoke:select-image` | 打开文件选择器 |
| 16 | `invoke:get-image-path` | 根据相对路径获取图片文件全路径 |

### 5 个事件通道（主进程 → 渲染进程）

| # | 事件名 | 功能 |
|---|--------|------|
| 1 | `on:device-discovered` | 发现新设备 |
| 2 | `on:device-offline` | 设备离线 |
| 3 | `on:connection-changed` | TCP 连接状态变化 |
| 4 | `on:message-received` | 收到新消息 |
| 5 | `on:retry-completed` | 消息重试完成 |

### 安全性

- preload 使用白名单机制，**指定通道名以外的一律不受理**
- 所有 IPC 请求都有 `code/message/data` 统一返回格式

## 五、前端架构

### 路由

| 路径 | 页面 | 说明 |
|------|------|------|
| `/` | DeviceList | 主界面：设备发现 + 最近联系人 |
| `/chat/:ip` | ChatWindow | 聊天详情页 |

### 状态管理（Pinia Store）

```javascript
// deviceStore — 设备与连接
{
  deviceList: [],           // UDP 发现的设备列表
  connectionStatus: {},     // IP → 'connected'|'connecting'|'disconnected'
  onlineTimers: {}          // 在线检测计时器
}

// chatStore — 聊天
{
  currentIp: '',
  currentName: '',
  messages: [],             // 当前聊天全部消息（全量加载，不分页）
  unsubscribers: [],        // 事件订阅取消函数
  loading: false
}

// userStore — 用户配置
{
  userName: ''
}
```

### 消息全量加载

之前使用分页（pageSize=40），但本地聊天消息量有限（通常几十到几百条），分页引入了多个 Bug（搞反页码、pageSize 不一致导致跳页）。

**改为全量加载**：进入聊天时通过 `invoke:get-all-messages` 一次性查出全部历史，简单可靠。

## 六、构建流程

```
npm run electron:build
       │
       ▼
  ① vite build ─► dist/ (Vue前端) + dist-electron/ (主进程)
       │
       ▼
  ② electron-builder ─► release/win-unpacked/LanChat.exe
```

输出为 **免安装文件夹**（`dir` 目标），双击 `LanChat.exe` 直接运行。
